## Units

### P0001-C03-a — failed writes to stdout

**Build:** in `src/jumble/cli.py`, per spec §4.1, §6, and DEC-14:
- A `BrokenPipeError` writing stdout (no `-o`, or `-o -`) exits 1 with
  nothing on stderr: no message, no traceback, no `Exception ignored` line
  at interpreter exit (point fd 1 at `os.devnull` before returning, as
  Python's signal docs show, so the exit-time flush has nowhere to fail).
- Any other `OSError` writing stdout prints
  `jumble: error: can't write stdout: REASON` (`strerror`) and returns 1.
- `-o FILE` failures stay as they are.
- README: the exit-1 sentence covers stdout too.
**Tests:** a subprocess test (`sys.executable -m jumble -c 200000`, stdout a
pipe the test reads one line from and then closes) exits 1 with stderr
exactly `b""`; with `sys.stdout` replaced by a text wrapper whose buffer's
`write` raises `OSError(errno.ENOSPC, "No space left on device")`, `main([])`
and `main(["-o", "-"])` each return 1 with stderr exactly
`jumble: error: can't write stdout: No space left on device\n`. (No
in-process `BrokenPipeError` test: pointing fd 1 at `os.devnull` inside
pytest would swallow pytest's own output.)
**Done when:** those tests pass and `jumble -c 200000 | head -1` prints one
line and nothing else.

### P0001-C03-b — layout, header, and live validation

**Build:** rewrite `src/jumble/tui.py` to spec §7.1:
- Header: title `jumble <version>` from `importlib.metadata.version("jumble")`;
  subtitle exactly `strength_line(strength(settings))` for the current
  controls, or empty while they are invalid.
- Controls pane: `Input`s for length and count (type integer; an
  unparsable value counts as 0), a scrollable list of all eighteen named
  sets in canonical order (`CHARSETS`), the custom `Input`, and checkboxes
  for the four options, labelled after README's option table. Initial values
  are `Settings()`'s (§7.5 comes next chunk).
- One function reads the controls into a `Settings`. On every change to any
  control it runs `strength` on it: success sets the subtitle and hides the
  banner; `JumbleError` shows its message in the banner and empties the
  subtitle (§6, §7.1). No `Settings` default fill: with nothing chosen the
  TUI shows `choose at least one character set`.
- Results pane: one row per string; `g` (and the jumble at start) generates
  with the controls' settings and replaces the rows; while invalid, `g`
  does nothing. No Jumble button (DEC-12).
- README: the TUI section describes the new layout.
**Tests:** at start the title is `jumble ` plus the package version and the
subtitle is `62 characters · 95.3 bits per string`; checking `each` makes
it `62 characters · at most 95.3 bits per string`; setting length to `0`,
then to empty, shows `length must be at least 1` in a visible banner with
an empty subtitle, and `g` then leaves the results unchanged; unchecking
every set shows `choose at least one character set`; custom `abc` with
`lower` checked shows the §6 custom message; fixing the control hides the
banner and restores the subtitle; `g` with length 24 and only `digits`
gives digit strings of length 24, count 5 gives 5 rows; the set list holds
the `CHARSETS` names in order.
**Done when:** those tests pass.

### P0001-C03-c — results cursor, copy keys, and focus

**Build:** per spec §7.1, §7.2, DEC-11, DEC-12:
- The results pane has a cursor that goes to the first string after each
  jumble. With more than 1000 strings it shows the first 1000 and a final
  `… and N more (s saves all)` row that can't be highlighted.
- `c` copies the highlighted string (toast `Copied`); `a` copies every
  string, all of them past 1000, joined by `\n` (toast `Copied N strings`,
  `Copied 1 string`). Before any strings, both do nothing. While invalid,
  both use the last result.
- Focus starts on the results pane. In any `Input`, `enter` jumbles (when
  valid) and moves focus to the results pane; `escape` moves it there
  without jumbling.
- Footer: `g` Jumble, `c` Copy, `a` Copy all, `q` Quit. `s`, `d`, and `,`
  are not bound yet.
- README: the TUI keys as built.
**Tests:** with count 1500, the pane has 1001 rows, the last reads
`… and 500 more (s saves all)`, moving the cursor to the end stops on the
1000th string, and `a` copies 1500 lines (patch `App.copy_to_clipboard` to
record) with toast `Copied 1500 strings`; `c` after moving the cursor down
one copies the second string; count 1 gives `Copied 1 string`; after making
the controls invalid, `a` still copies the last result; focus is on the
results pane at start; `enter` in the length input jumbles (results change)
and focuses the results pane; `enter` while invalid moves focus and leaves
the results; `escape` moves focus without jumbling.
**Done when:** those tests pass, and README's TUI section, the footer, and
spec §7.2 agree on the four keys built.
