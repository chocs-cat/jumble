# Chunk P0001-C02 — command-line output

**Goal:** the command line writes its output the way spec §4 says:
generate everything, then write (§4.1, DEC-8), to stdout or `-o FILE`, always
UTF-8; `--json` (§4.2); `--strength` (§4.3); a write failure exits 1 and the
`tui` misuse errors exit 2 (§4, §6). This is P0001's delivery item D2 in full.
It comes before the TUI rebuild (D3) because D3's subtitle reuses the
strength line built here, and D4's settings file builds on the effective
settings `--json` first reports.

## Units

### P0001-C02-a — generate, then write; `-o`

**Build:** in `src/jumble/cli.py`:
- `-o/--output FILE` (default `None`, so `-o -` is distinguishable from not
  giving it; §4's table). `-o -` and no `-o` both write to stdout.
- Generate every string first, then build the whole output and write it as
  UTF-8 bytes (§4.1, DEC-8): to stdout's binary buffer, whatever
  `sys.stdout`'s text encoding, or to `FILE`, created or overwritten. Lines
  output is each string and `\n`.
- An `OSError` opening or writing `FILE` prints
  `jumble: error: can't write FILE: REASON` (FILE as given, REASON the
  error's `strerror`) to stderr and returns 1 (§6).
- `-a`'s help lists the look-alikes in §3.1's order (C01 review finding 3);
  take the order from one place rather than retyping it.
- README and help: `-o` in the options table.
**Tests:** `-o FILE` writes the strings as UTF-8 lines with nothing on
stdout, and a second run overwrites a longer existing file completely;
`-o -` prints to stdout; with `sys.stdout` monkeypatched to
`io.TextIOWrapper(io.BytesIO(), encoding="ascii")`, `-s emoji-faces -n 8`
writes bytes that decode as UTF-8 to an 8-code-point line; a `unique` run
that gives up (`secrets.randbelow` patched to 0, `-s digits -c 2 -u -o FILE`)
exits 2, prints nothing to stdout, creates no file, and leaves a
pre-existing `FILE` byte-identical; `-o tmp_path/missing/out.txt` exits 1
with exactly `jumble: error: can't write …/missing/out.txt: No such file or
directory` as stderr; `-a`'s help lists the look-alikes in §3.1's order.
**Done when:** those tests pass.

### P0001-C02-b — `--json`

**Build:**
- In `generate.py`, a public function giving a `Settings`' §1 values as a
  dict in §1's key order, with `charsets` each chosen named set once in
  canonical order and `custom` as given (§4.2). D4 and D5 will reuse it.
- In `cli.py`, `--json` writes the §4.2 object, keys in the order shown,
  through unit a's output path (so `-o` and UTF-8 apply):
  `alphabet_size` and the rounded `strength_bits` from `strength(...)`,
  `strength_is_bound` from it too, `settings` from the dict above, built from
  the effective `Settings` (after the default-set fill, DEC-9). Formatting:
  `json.dumps(obj, indent=2, ensure_ascii=False)` and `\n`.
- README and help: `--json` and an example object.
**Tests:** the default run's output parses, its keys are exactly the §4.2
list in order, and it equals `json.dumps(parsed, indent=2,
ensure_ascii=False) + "\n"`; defaults give `alphabet_size` 62,
`strength_bits` 95.3, `strength_is_bound` false, and `settings` equal to
§1's defaults; `-s digits,lower,lower` gives `charsets` `["lower",
"digits"]`; `--custom aab` alone gives `charsets` `[]` and `custom` `"aab"`;
`-e` sets `strength_is_bound`; an emoji set's strings appear unescaped in
the raw output; `--json -o FILE` writes the object to the file and nothing
to stdout; `--json -n 0` prints the plain `jumble: error: …` line, not JSON,
and nothing to stdout.
**Done when:** those tests pass.

### P0001-C02-c — `--strength` and the `tui` misuse errors

**Build:**
- In `generate.py`, `strength_line(strength: Strength) -> str`, the §4.3
  wording: `A characters · B bits per string`, `at most` before the bits when
  `is_bound`, `1 character` when *A* is 1, bits with exactly one decimal
  place. D3's subtitle calls it.
- In `cli.py`, `--strength` writes that line and `\n` to stderr after the
  output is written, only when the run succeeds (§4.3).
- `-o`, `--json`, or `--strength` with `tui` is
  `parser.error("OPTION can't be used with tui")`, OPTION the long name of
  the first of `--output`, `--json`, `--strength` given, in that order (§4,
  §6). `-o -` counts as given. Check this before opening the TUI or touching
  any file.
- README and help: `--strength`, and the note that these three don't go
  with `tui`. Then README and `jumble --help` cover every option of §4 but
  `--no-config` (D4).
**Tests:** `strength_line` gives `62 characters · 95.3 bits per string` for
the defaults, the `at most` form with `each`, `1 character · 0.0 bits per
string` for `-s space`, and `3.0` (not `3`) for `--custom ab -n 3`;
`--strength` prints the strings to stdout and exactly the line to stderr;
with `-o FILE` stdout stays empty and the line still goes to stderr;
`--strength -n 0` prints only the error line; `-o x tui`, `-o - tui`,
`--json tui`, and `--strength tui` each exit 2 with stderr starting with
`usage:` and ending `jumble: error: --output can't be used with tui` (or
`--json`, `--strength`); `--strength --json tui` names `--json`; no file
`x` is created.
**Done when:** those tests pass, and README, `jumble --help`, and spec §4
agree on every option this chunk built.

## Notes for the executor

- `capsys` captures writes to `sys.stdout.buffer`, so the existing CLI tests
  keep working once output goes through the binary buffer; flush the text
  layer first if anything else ever printed to it.
- Put the misuse check after `parse_args` and before the `tui` branch; the
  other options are top-level, so `jumble tui -o x` is argparse's own
  "unrecognized arguments" error and needs nothing from you.
- `strength(...)` validates, so compute it from the same `Settings` you
  generate from, and only after `generate` has succeeded, so the error a
  failed run prints is `generate`'s.
