## Units

### P0001-C04-a — a give-up is a toast

**Build:** in `src/jumble/tui.py`, per spec §7.1 and DEC-15: when `generate`
raises `JumbleError` during a jumble (`g`, `enter`, and the start-up jumble
all go through one method), show `str(e)` in a toast with
`severity="error"` and leave `strings`, the rows, and the cursor as they
were. The banner is not touched. No §6 message is retyped.
**Tests:** with `jumble.tui.generate` patched to raise
`JumbleError("gave up after 100000 draws with 9 of 10 unique strings")` after
a first good jumble, `g` leaves the app running, the rows and the highlighted
index unchanged, the banner hidden, and one error notification with exactly
that message (read `app._notifications`, or patch `App.notify` to record);
the same through `enter` in `#length`. The test must fail with the
`try`/`except` removed (`brief-checklist §3`): check it does.
**Done when:** those tests pass.

### P0001-C04-b — starting values from the command line

**Build:** per spec §7.5 and DEC-16:
- `JumbleApp(settings: Settings = Settings())`: every control starts from
  `settings` (length, count, the selected sets, custom, the four options),
  and the subtitle, banner, and start-up jumble follow from them as they
  would after a change. An invalid start shows the banner and jumbles
  nothing.
- In `src/jumble/generate.py`, one function that raises §6's
  `unknown character set: 'NAME'` for the first name not in `CHARSETS`;
  `chosen_sets` uses it, so the message has one home.
- `cli.main`'s `tui` branch: after the misuse check, build
  `settings_from(args)`, run that name check (on `JumbleError`, print
  `jumble: error: MESSAGE` and return 2, as the generating path does), then
  `JumbleApp(settings).run()`.
- `jumble tui --help` and the subcommand's help say options before `tui` set
  its starting values. README's TUI section says so too, with the example
  `jumble -n 32 -s digits tui`.
**Tests:** `JumbleApp(Settings(length=32, charsets=("digits",)))` starts with
`#length` `32`, only `digits` selected, the subtitle for a 10-character
alphabet at 32, and one 32-digit row; each option and custom reach their
control; `JumbleApp(Settings(length=0))` starts with the banner showing
`length must be at least 1`, no rows, and `c` and `a` copying nothing;
`main(["-s", "foo", "tui"])` returns 2 with stderr exactly
`jumble: error: unknown character set: 'foo'\n` and never builds the app

"digits", "tui"])` and `main(["tui"])` hand `run` an app whose settings are

**Done when:** those tests pass and `jumble -n 32 -s digits tui` opens on
32-digit strings.

### P0001-C04-c — `s` saves the strings, and the screenshot

**Build:** per spec §7.3, §7.2, DEC-13:
- `s` writes the last result's strings to `jumble-<epoch>-<count>.txt` in the
  current directory, opened with `"xb"`, bytes
  `"".join(f"{s}\n" for s in strings).encode()`. Toasts: `Saved NAME`;
  on `FileExistsError` the error toast `NAME exists; nothing saved`; on any
  other `OSError` the error toast `can't save NAME: REASON` (`strerror`),
  removing nothing that existed before. Before any strings, `s` does
  nothing; while invalid, it saves the last result.
- Footer: `g` Jumble, `c` Copy, `a` Copy all, `s` Save, `q` Quit. `d` and
  `,` stay unbound.
- README's TUI keys table gains `s`; spec §7.2, the footer, and README agree.
- A screenshot: `docs/tui.svg`, saved with `app.save_screenshot` from a
  `run_test(size=(100, 30))` of `JumbleApp(Settings(count=10))`, shown in
  README's TUI section and linked from the pull request body. It is a docs
  asset, made by hand once; no test regenerates it.
**Tests:** with `time.time` patched to `1760000000.7` and the working
directory a `tmp_path`, count 1500 then `s` writes
`jumble-1760000000-1500.txt` holding exactly the 1500 strings each followed
by `\n` (all of them, not the shown 1000, DEC-11) and toasts
`Saved jumble-1760000000-1500.txt`; a second `s` in the same second leaves
the file's bytes unchanged and toasts
`jumble-1760000000-1500.txt exists; nothing saved` with severity error; with
the directory read-only (`chmod 0o500`, restored after), `s` toasts
`can't save jumble-1760000000-1500.txt: Permission denied` and leaves no
file; a `--custom` set of emoji saves as UTF-8; after making the controls
invalid, `s` saves the last result; before any strings, `s` writes nothing;
the shown bindings are exactly g, c, a, s, q.
**Done when:** those tests pass and `docs/tui.svg` shows the layout of
spec §7.1.

## Notes for the executor

- `App.notify(message, severity="error")` is the error toast; tests can read
  the recorded calls by patching `notify` on the instance.
- Setting a widget's value in `on_mount` posts a `Changed` message; the
  validation it triggers runs after mount. Set the controls in `compose`
  (constructor arguments) so the first `check()` sees them.
- If the 3.5 s subprocess pipe test bothers you, a smaller `-c` that still
  overflows stdout's buffer (`-c 2000`, 34 KB) keeps its purpose; leave it
  unless a timing shows the gain.
