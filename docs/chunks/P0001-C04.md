### P0001-C04-c — `s` saves the strings, and the screenshot

**Build:** per spec §7.3, §7.2, DEC-13:
- `s` writes the last result's strings to `jumble-<epoch>-<count>.txt` in the
  current directory, opened with `"xb"`, bytes
  `"".join(f"{s}\n" for s in strings).encode()`. Toasts: `Saved NAME`;
  on `FileExistsError` the error toast `NAME exists; nothing saved`; on any
  other `OSError` the error toast `can't save NAME: REASON` (`strerror`),
  removing nothing that existed before. Before any strings, `s` does
  nothing; while invalid, it saves the last result.
- Footer: `g` Jumble, `c` Copy, `a` Copy all, `s` Save, `q` Quit. `d` and
  `,` stay unbound.
- README's TUI keys table gains `s`; spec §7.2, the footer, and README agree.
- A screenshot: `docs/tui.svg`, saved with `app.save_screenshot` from a
  `run_test(size=(100, 30))` of `JumbleApp(Settings(count=10))`, shown in
  README's TUI section and linked from the pull request body. It is a docs
  asset, made by hand once; no test regenerates it.
**Tests:** with `time.time` patched to `1760000000.7` and the working
directory a `tmp_path`, count 1500 then `s` writes
`jumble-1760000000-1500.txt` holding exactly the 1500 strings each followed
by `\n` (all of them, not the shown 1000, DEC-11) and toasts
`Saved jumble-1760000000-1500.txt`; a second `s` in the same second leaves
the file's bytes unchanged and toasts
`jumble-1760000000-1500.txt exists; nothing saved` with severity error; with
the directory read-only (`chmod 0o500`, restored after), `s` toasts
`can't save jumble-1760000000-1500.txt: Permission denied` and leaves no
file; a `--custom` set of emoji saves as UTF-8; after making the controls
invalid, `s` saves the last result; before any strings, `s` writes nothing;
the shown bindings are exactly g, c, a, s, q.
**Done when:** those tests pass and `docs/tui.svg` shows the layout of
spec §7.1.

### What landed

**a — a give-up is a toast.** `JumbleApp.action_jumble` (the one path for
`g`, `enter`, and the start-up jumble) catches `JumbleError` from `generate`,
shows `str(e)` with `severity="error"`, and returns before touching
`strings`, the rows, or the cursor; the banner is not touched (§7.1, DEC-15).

**b — starting values.** `JumbleApp(settings: Settings = DEFAULTS)` stores
`self.initial` and builds every control from it in `compose`, so the first
`check()` in `on_mount` sees them; an invalid start shows the banner and the
start-up jumble does nothing. `generate.check_names(charsets)` is the one
home of `unknown character set: 'NAME'`; `chosen_sets` calls it. `cli.main`'s
`tui` branch, after the misuse check, builds `settings_from(args)`, runs
`check_names`, prints `jumble: error: MESSAGE` and returns 2 on failure, else
runs `JumbleApp(settings)`. No second default fill in the TUI. The `tui`
subcommand's help and its new `description` (`jumble tui --help`) say options
before `tui` set its starting values, with `jumble -n 32 -s digits tui`;
README's TUI section and examples block say so too.

**c — `s` and the screenshot.** `action_save` writes
`jumble-<int(time.time())>-<len(strings)>.txt` with `open(name, "xb")` and
the §4.1 bytes. Toasts: `Saved NAME`; `NAME exists; nothing saved` (error);
`can't save NAME: REASON` (error, `strerror`) for any other `OSError` from the
create or the write. A failed write removes the file the exclusive create
just made (so only ever our own partial file), suppressing a failed removal.
The footer is g, c, a, s, q. README: `s` row in the keys table, a paragraph on
never overwriting, and `docs/tui.svg` embedded. The screenshot was taken by
hand from `run_test(size=(100, 30))` of `JumbleApp(Settings(count=10))`.

Deviation: none from the brief. One addition beyond it: the write-failure
branch's cleanup, which §7.3's "leaves no partial file" requires and the
