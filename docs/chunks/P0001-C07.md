## Units

### P0001-C07-a — the `,` settings screen
**Build:** per spec §5.2, §7.1, §7.2, §7.4 and DEC-20:
- In `src/jumble/config.py`, `file_settings(file: Mapping[str, object]) ->
  Settings`: the built-in defaults, then what `load` returned, merged as
  §5.2 merges them with no command line (characters as a whole; the default
  sets when the file chooses none). `cli.settings_from` is rebuilt on it,
  so there is one merge; every existing CLI test passes unchanged.
- In `src/jumble/tui.py`, one function that builds the controls (length,
  count, the set list, custom, the four options, with their labels and
  border titles) from a `Settings`, and one that reads a `Settings` back
  from the screen holding them (`parse_int` for the numbers). The main
  screen and the form both use them.
- A `SettingsScreen` (a `ModalScreen`) holding the controls, the §5.1 path
  as it resolves on opening, and Save and Cancel buttons. `JumbleApp` binds
  `,` (Textual's `comma`) → open it, footer label `Settings`, after `d`.
  Opening it calls `load(config_path())` and fills the controls with
  `file_settings` of the result; a `JumbleError` fills them with
  `Settings()` and shows its message in an error toast.
- Save (the button, or `enter` in a form input): run the banner's check
  (`strength`, as `check` does) on the form's settings; a `JumbleError` is
  an error toast and the screen stays open. Otherwise call
  `save(config_path(), settings)`, resolving the path then; its
  `JumbleError` is an error toast and the screen stays open. On success,
  close the screen, set all eight main-screen controls to the saved values,
  run the main screen's `check`, and toast `Saved defaults to PATH`. No
  jumble.
- Cancel and `escape` close the screen and change nothing.
- The form's messages stop at its screen (or the App's handlers ignore
  messages from other screens), so none reaches `JumbleApp`'s handlers.
- README: the TUI keys table gains `,`; the *Settings file* section says
  the settings screen edits the file, filled from it, and repairs a broken
  one.
**Tests:** query the form through `app.screen`; before pressing letter keys,
focus a checkbox (AGENTS.md *Testing notes*).
- `,` opens the screen; `test_footer_keys` becomes g, c, a, s, d, `,`, q,
  with `,` labelled `Settings`.
- Filling: a file of `length = 24` and `custom = "abc"` fills length 24, no
  set checked, custom `abc`, the rest at defaults, while the main screen
  started from `Settings(length=8)` (as `-n 8 tui` would) keeps 8; a missing
  file and a file of `charsets = []` fill the defaults with the default sets
  checked. For these files and one setting every key to a non-default
  value, `settings_from(parser().parse_args([]), file) ==
  file_settings(file)`, and the form's reader returns `file_settings(file)`.
- The path shown is `str(config_file)`; with `$JUMBLE_CONFIG` set to
  `./rel/config.toml` it is `rel/config.toml`.
- A file of `length = 0` fills the defaults, toasts
  `{config_file}: length: length must be at least 1` as an error, and Save
  writes a file `load` accepts. A directory at the path fills the defaults,
  toasts `can't read {config_file}: Is a directory`, and Save toasts
  `can't save {config_file}: Is a directory` with the screen still open and
  the main controls unchanged.
- A valid Save writes what `load` reads back as the form's values, closes
  the screen, and leaves `app.settings()` equal to them, the banner hidden,
  the subtitle their `strength_line`, `app.strings` as before, and the toast
  `Saved defaults to {config_file}`; started from `Settings(length=0)` (the
  banner showing), the banner is hidden after the Save.
- `enter` in the form's custom input saves the same way and leaves
  `app.strings` unchanged. This is the bubbling trap: check that the test
  fails when the form's `Input.Submitted` reaches `JumbleApp`
  (`brief-checklist §3`).
- Typing `0` into the form's length leaves the main banner hidden and
  `app.settings()` unchanged until a Save.
- An invalid form (length 0; and `each` with length 2 and three sets)
  writes nothing (the file stays missing), keeps the screen open, and
  toasts its §6 message as an error.
- Cancel, and `escape` from inside a form input, close the screen; the
  file's bytes, the main controls, and the toasts are unchanged.
- With a form checkbox focused, `g`, `c`, `a`, `s`, `d`, `,`, and `q` do
  nothing: the app runs, one settings screen is open, `app.strings` is
  unchanged, no file appears in a `tmp_path` working directory or at
  `config_file`, and no toast shows.
**Done when:** those tests pass, `,` is in the footer, and README covers the
screen.
