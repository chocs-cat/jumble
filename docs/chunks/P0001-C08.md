# Chunk P0001-C08 — bare `jumble` opens the TUI

**Goal:** P0001's D6, from issue #20. `jumble` typed alone at a prompt
opens the TUI, exactly as `jumble tui` does, while a piped or scripted
`jumble`, and `jumble` with any argument, print as before (spec §4, §7,
DEC-21). It is the last delivery item; after it `/relay-project` closes
P0001.

## Kickoff notes

- The pull request title is `feat(cli)!: …` (bare `jumble` in a terminal
  used to print), and its body says `Fixes #20`.
- One unit. The rule is two conditions, and both are traps: *no arguments*
  is the list argparse parses (`argv`, or `sys.argv[1:]` when `main` gets
  `None`), and *a terminal* is stdin **and** stdout. A check of stdout
  alone opens a TUI on `echo | jumble`; tests must fail that mutation.
- Bare `jumble` in a terminal is `jumble tui`, not a lookalike: same
  settings file handling, same file-error toast, same `JumbleApp` start.
  Route it through the existing `tui` branch rather than a second launch.
- Tests: under `pytest -s` in a real terminal, stdin and stdout are both
  TTYs (probed at this cut), so the existing `main([])` tests would open a
  TUI and hang. Make the non-interactive case the default for every test.
- The reviewer repeats the real-terminal run.

## Units

### P0001-C08-a — bare `jumble` in a terminal opens the TUI
**Build:** per spec §4, §7, and DEC-21:
- In `src/jumble/cli.py`, `main` decides on the argument list it is about
  to parse (`argv`, or `sys.argv[1:]` when `argv` is `None`): when it is
  empty and `sys.stdin.isatty()` and `sys.stdout.isatty()` are both true,
  it runs exactly as `main(["tui"])` would. Otherwise nothing changes.
  Cite DEC-21 at the code site.
- `jumble --help`: the description or usage text says bare `jumble` opens
  the TUI in a terminal and prints otherwise; `jumble tui --help` keeps its
  wording.
- README: the *Usage* block's first line becomes bare `jumble` opening the
  TUI, with a printing example for one string (`jumble -c 1`, or a pipe);
  *The TUI* says how it opens (bare `jumble`, or `jumble … tui` with
  starting options). Keep the README, help, and spec §4 saying the same.
- `tests/conftest.py`: an autouse fixture that makes stdin report it is
  not a terminal for every test (for example, `monkeypatch.setattr(sys,
  "stdin", io.StringIO(""))`), so `main([])` prints under `pytest -s` too.
  Tests of the terminal case set their own streams.
**Tests:** with `Launched` (in `test_cli.py`) recording instead of running:
- For each of the four stdin/stdout terminal combinations (stand-in
  streams whose `isatty()` returns the chosen value, with stdout still
  capturable), `main([])` opens the TUI only when both are terminals, and
  in the other three prints one 16-character default string and opens
  nothing. This catches a check of either stream alone
  (`brief-checklist §3`); name both mutations in the report.
- With both streams terminals: `main([])` starts `JumbleApp` from the
  same settings and the same `file_error` as `main(["tui"])`, for a
  settings file with values and for a broken one (`length = 0`); with
  `main(["--no-config"])`, `main(["-c", "1"])`, and `main(["-n", "16"])`
  it prints and opens nothing.
- `main(None)` with `sys.argv` set to `["jumble"]` and both terminals opens
  the TUI; with `["jumble", "-c", "1"]` it prints.
- A subprocess `jumble` with no arguments (pipes, not terminals) prints one
  string and exits 0.
- The help text test pins the new wording.
**Done when:** those tests pass; README, `jumble --help`, and spec §4
agree; the report pastes a tmux run (100 × 30, `$JUMBLE_CONFIG` on a
scratch file) of bare `jumble` showing the TUI, `q` exiting 0, and
`jumble | cat` printing one string.
