## Units

### P0001-C01-a — the sets, the settings type, and the alphabet

**Build:** in `src/jumble/generate.py`:
- `CHARSETS: dict[str, str]`, the eighteen named sets of spec §2.1 with
  exactly their characters, inserted in canonical order (the dict's order *is*
  the canonical order). `symbols` is `string.punctuation` (DEC-2). Spell
  ranges as code (`chr` over the spec's ranges and exclusions), not as pasted
  glyphs, except `math` and `currency`, which the spec lists literally.
- `AMBIGUOUS`, a frozenset of the DEC-3 look-alikes (§3.1).
- `Settings`, a frozen dataclass with the eight fields of §1, in §1's order
  and with its defaults; `charsets` is `tuple[str, ...]` defaulting to
  `("lower", "upper", "digits")`. It holds what it was given (names in any
  order, duplicates and unknown names included); validation judges it.
- `JumbleError(ValueError)`: every §6 message is raised as one, with the
  message as its text.
- The §2.3 custom rules: dedupe keeping first position; a character in
  category `Cc`, `Cf`, `Cs`, `Co`, `Cn`, or `M*` is an error. `custom` is not
  a named set (§2.2).
- The §2.4 build, as a function returning the chosen sets as an ordered list
  of `(name, characters)` pairs after steps 1–3 (canonical order, `custom`
  last, only when non-empty before step 1). D2's `--json` reuses this order.
**Tests:** for each named set, its characters equal an expected value the
test builds from the spec's ranges itself, its size is the §2.1 size, and no
character is in category `C*` or `M*`; `CHARSETS`' keys are the §2.1 names in
order; `AMBIGUOUS` is exactly the §3.1 list; custom dedupe keeps first
positions; overlaps stay in the earlier set (`lower` + `--custom abcX` gives
custom `X`); `no_ambiguous` removes look-alikes from `custom` too.
**Done when:** those tests pass and `Settings()` equals §1's defaults.

### P0001-C01-b — validation and strength

**Build:**
- `validate(settings)` runs every §6 check in the table's order, raising
  `JumbleError` with the first failing message, and returns the §2.4 sets.
  The "no characters chosen" row applies here whenever `charsets` and
  `custom` are both empty; the CLI never reaches it because it fills the
  default sets first (unit d). Numbers in messages are plain integers (§6).
- `strength(settings)` returns a small named tuple of alphabet size *A*,
  strength in bits (a float, `log₂ P`, unrounded; callers round to one
  place), and whether it is a bound (`each` on). *P* per §3.5: `A ** length`,
  or `math.perm(A, length)` with `no_repeat`. Take `log₂` of the integer, never
  of a float power, so long strings don't overflow.
**Tests:** one test per §6 row that fires it with its exact message (every row
except "gave up", which is unit c); for each adjacent pair of rows that can
both fail, a settings value failing both gets the earlier message (for
example length 0 with an unknown set gives the length message); the `each`
message names *K*, counting `custom` as a set; `no_repeat` with `length = A`
validates and `A + 1` fails; `unique` with count `P` validates and `P + 1`
fails; strength matches `16 × log₂ 62` for the defaults and
`log₂(62!/46!)` with `no_repeat`, rounded to 95.3 for the first; with `each`
the bound flag is set and the bits are unchanged.
**Done when:** every §6 row but the last is pinned by a test, and strength
matches both §3.5 formulas.

### P0001-C01-c — generation

**Build:** `generate(settings) -> list[str]`: validates, then draws `count`
strings of `length` characters per §3.2–§3.4, every draw through
`secrets.randbelow` (DEC-1, DEC-6). `no_repeat` without `each` is a partial
Fisher–Yates sample of the alphabet; `each` draws one character from each
set, fills from the whole alphabet (without already-drawn characters when
`no_repeat` is on), and shuffles with Fisher–Yates (DEC-6). `unique` keeps
drawn order, redraws a repeat, and after `max(100000, 20 × count)` draws in
total without `count` distinct strings raises
`gave up after D draws with N of COUNT unique strings`, *D* being that cap
(§3.4, DEC-7). Remove the old `alphabet()` and the `exclude_ambiguous`
keyword; export `Settings`, `JumbleError`, `validate`, and `strength` from
`jumble/__init__.py` beside `CHARSETS` and `generate`.
**Tests:** lengths and count; every character in the alphabet; `no_repeat`
strings have no repeated character, also at `length = A`; `each` strings hold
a character of every chosen set, `custom` included, also at `length = k` and
with `no_repeat`; `unique` output has no duplicates (e.g. `digits`, length 2,
count 100, which forces all 100); an impossible `unique` count fails before
any draw (patch `secrets.randbelow` to fail the test if called); with
`secrets.randbelow` patched to return 0, `unique` with count 2 raises
`gave up after 100000 draws with 1 of 2 unique strings`; a test reads every
`.py` file under `src/` and fails on an `import random`, a `from random`, or
`SystemRandom`.
**Done when:** those tests pass.

### P0001-C01-d — the command line, help, and README

**Build:** in `src/jumble/cli.py`, per spec §2.2, §2.3, and §4's table:
- `-s/--charset` repeatable, each value split on commas; no argparse
  `choices` (validation reports unknown and empty names, §2.2, §6). Its help
  lists the set names.
- `--custom CHARS`, `-e/--each`, `-r/--no-repeat`, `-u/--unique`; `-a`'s help
  lists the §3.1 characters.
- Build one `Settings`: `charsets` from `-s` (or empty), `custom` from
  `--custom`; when both are empty, the default sets (§1, DEC-9). Print each of
  `generate(settings)`'s strings on its own line. A `JumbleError` prints
  `jumble: error: MESSAGE` to stderr, with no usage line, and returns 2 (§6).
- Keep `src/jumble/tui.py` working with the least change: build a `Settings`
  and show `generate(...)[0]`; its checkboxes stay the four ASCII sets (a
  local tuple), since eighteen would not fit its row. D3 rebuilds it.
- README.md: the usage examples, a table of the eighteen sets (name, what it
  holds, size), and the new options. Don't document `-o`, `--json`,
  `--strength`, or `--no-config`; they arrive in later chunks.
**Tests:** `-s lower,digits` and `-s lower -s digits` give the same alphabet;
`jumble --custom abc` prints only `abc` characters; `--custom abc -s lower`
exits 2 with the custom message; an unknown set and `-s lower,` each exit 2
with `jumble: error: unknown character set: …` as the whole stderr; `-e`,
`-r`, `-u` reach the settings (one CLI test each, checking their effect on
the output); `-n 0` exits 2 with the length message.
**Done when:** those tests pass, the TUI test passes unchanged in intent, and
`jumble --help` and README agree with spec §2 and §4 for the options built
here.

### What landed

**a.** `src/jumble/generate.py` has `CHARSETS` (the eighteen §2.1 sets in
canonical order, with ranges spelled as `_span(first, last, without=…)` and
`math`/`currency` literal), `AMBIGUOUS` (a frozenset of the 15 DEC-3
characters), the frozen `Settings` dataclass (§1's eight fields, order, and
defaults), `JumbleError(ValueError)`, the §2.3 custom rules (`_custom_chars`),
and `chosen_sets(settings)`, the §2.4 build (steps 1–3), returning
`[(name, chars), …]` in canonical order with `custom` last. `chosen_sets` runs
the §6 rows from "unknown set name" through "a chosen set is empty" in order,
so the build can't run on names it doesn't know. **Deviations:** the TUI's
switch to a local four-set tuple (brief unit d) landed here, because
iterating the new `CHARSETS` would have put eighteen checkboxes in its row and
broken `tests/test_tui.py`. Ruff's look-alike rules (RUF001–003) are off for
`generate.py` and `tests/test_sets.py` in `pyproject.toml`, since those
files are full of look-alikes by design.

**b.** `validate(settings)` checks length, then count, then calls
`chosen_sets`, then checks the `each`, `no_repeat`, and `unique` rows, and
returns the sets. `strength(settings)` returns `Strength(alphabet_size, bits,
is_bound)`, a named tuple. It validates first, so *A* comes from the same
sets, and takes `math.log2` of the exact integer *P* (`A**length` or
`math.perm(A, length)`).

**c.** `generate(settings) -> list[str]` validates, then draws. Every draw is
a `secrets.randbelow` call made through the module attribute: plain indexing,
a partial Fisher–Yates `_sample` for `no_repeat`, and for `each` one pick per
set, a fill (a sample of the alphabet without the picks under `no_repeat`),
then a Fisher–Yates `_shuffle`. `unique` keeps a dict in drawn order and
raises the §6 give-up message once the draw count reaches
`max(100000, 20 × count)`. The old `alphabet()` and `exclude_ambiguous` are
removed, and `jumble/__init__.py` exports `CHARSETS`, `JumbleError`,
`Settings`, `generate`, `main`, `strength`, and `validate`. **Deviation:**
`cli.py` and `tui.py` switched to building a `Settings` in this commit, the
smallest change that kept them running once the old API was gone. Unit d then
added the CLI's options.

**d.** `cli.py` handles `-s/--charset` (repeatable, split on commas, no
`choices`, help listing the eighteen sets), `--custom`, `-e`, `-r`, `-u`,
and `-a`, whose help lists the look-alikes. `-n` and `-c` show the metavar
`N`, as in §4. `settings_from(args)` builds one `Settings` and applies the
default sets only when `-s` and `--custom` are both empty (DEC-9). A
`JumbleError` prints `jumble: error: MESSAGE` and nothing else to stderr,
and exits 2. `tui.py` builds a `Settings` and shows `generate(...)[0]`. README
has usage examples, an options table, the rules for overlaps and errors, and
the eighteen-set table with sizes. It does not cover `-o`, `--json`,
`--strength`, or `--no-config`.
