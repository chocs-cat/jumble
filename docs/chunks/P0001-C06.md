# Chunk P0001-C06 — saving settings, and `d`

**Goal:** the first half of D5. `config.save` writes the settings file per
spec §5.3 with tomlkit, keeping comments and changing only what differs, and
the TUI's `d` key saves the current controls as the defaults (§7.4). After
this, P0001-C07 adds the `,` settings screen on top of the same `save`.

## Kickoff notes

- The pull request title is `feat(tui): …` (`d` is the user-visible change).
- §5.3's numbered steps, value formats, and template, and §7.4's save
  paragraph, were pinned at this cut with DEC-18. Build them as written.
- The trap: Python's `True == 1` and tomlkit's own item types. "Equal" in

  untouched-line branch is the one the tests lean on.

  `d`-specific so it can call it unchanged.

## Units

### P0001-C06-a — `config.save`
**Build:**
- `uv add tomlkit` (a runtime dependency, DEC-10); commit `pyproject.toml`
  and `uv.lock` with this unit.
- In `src/jumble/config.py`: `TEMPLATE`, the §5.3 template exactly, and
  `save(path: Path, settings: Settings) -> None` per §5.3's four steps: a
  missing, non-UTF-8, or unparsable file starts from `TEMPLATE`; unknown
  top-level keys (tables included) are removed; each §1 key, in §1's order,
  is left alone when its unwrapped value has the saved value's type and
  value, replaced in place otherwise, and appended when absent; the result
  is written as UTF-8 in place (following a symlink), after creating missing
  parent directories. `charsets` is written as a list in canonical order,
  which `Settings` already holds.
- Any `OSError` reading an existing file or writing raises `JumbleError`
  with `can't save PATH: REASON` (§7.4, `REASON` = `strerror`, `PATH` =
  `str(path)` as §5.1 now says).
**Tests:** `TEMPLATE` equals the fenced block under "The template" in
`docs/spec.md` §5.3, read from the file (so neither copy drifts). A save to
a missing file at `tmp_path/a/b/config.toml` creates the directories and
writes `TEMPLATE` with the saved values, and `load` of it returns all eight
keys equal to the saved `Settings`; saving `Settings()` there gives exactly
`TEMPLATE`. Saving the same settings twice leaves the bytes identical. A
commented file with every key (comments above lines and after values)
saved with one changed value differs from the original in that one line,
its trailing comment kept. A file with `length = true` saved with
`length = 1`, and one with `each = 0` saved with `each = False`, is
rewritten to `length = 1` and `each = false` (this must fail with a plain
`==` comparison: check it does, `brief-checklist §3`); `length = 16.0` with
16 likewise. A file of `colour = 1` and a `[extra]` table loses both. A file
missing `custom` gets `custom = ""` appended at the end. Non-UTF-8 bytes and
`length = ` each become the template with the saved values. A symlink to a
file is still a symlink after the save and its target holds the new
content. A directory at the path is `can't save PATH: Is a directory`; a
read-only file (`chmod 0o444`) is `can't save PATH: Permission denied`.
**Done when:** those tests pass and `save` is the only writer of the
settings file.

### P0001-C06-b — the `d` key
**Build:** per spec §7.1, §7.2, §7.4, DEC-18:
- `JumbleApp` binding `d`, footer label `Save defaults`, after `s`.
- While the controls are invalid, `d` writes nothing and shows the banner's
  §6 message in an error toast. Otherwise it calls
  `save(config_path(), self.settings())`, resolving the path at the time of
  the save (so `--no-config` doesn't stop it), and toasts
  `Saved defaults to PATH`; a `JumbleError` from `save` is an error toast
  with its message.
- README: the TUI keys table gains `d`; the *Settings file* section says the
  TUI's `d` writes it, keeping comments, and that a broken file is repaired
  by saving over it.
**Tests:** with focus on the results pane (AGENTS.md *Testing notes*):
`d` writes the controls to `config_file`, and `load` returns them, with the
toast `Saved defaults to {config_file}`; after `-n 0` (an invalid start) `d`
writes nothing (the file stays missing) and toasts `length must be at least
1` as an error; `JumbleApp(Settings(length=8), file_error=…)` over a file
of `length = 0` saves a file that `load` accepts with length 8 (DEC-17's
repair); a directory at `config_file` gives the error toast `can't save
{config_file}: Is a directory`; the footer shows `Save defaults`.
**Done when:** those tests pass, and a file `d` wrote is read back by the
command line: a test saves through the app, then runs `main(["--json"])`
and finds the saved settings.

## Notes for the executor

- `tomlkit.parse` keeps a value's trailing comment when you assign
  `doc[key] = new`, and `del doc[key]` removes the line; appending a new key
  lands at the end. Check each against a test rather than trusting this.
- Read with `path.read_bytes()` as `load` does, then decode and parse, so
  `FileNotFoundError` (template), other `OSError` (`can't save`), and
  `UnicodeDecodeError` or `tomlkit`'s parse error (template) stay separate
  steps.
- `path.write_bytes` follows a symlink; `path.parent.mkdir(parents=True,
  exist_ok=True)` before it. Don't `resolve()` the path for messages.
- Compare `type(old) is type(new) and old == new` on unwrapped values, with
  `charsets` compared as lists.

### What landed

**a — `config.save`.** `tomlkit` is a runtime dependency (`>=0.15.1`,
`pyproject.toml` and `uv.lock`). `src/jumble/config.py` has `TEMPLATE`
(spec §5.3's template, byte for byte), `_document(path)` (§5.3 step 1), and
`save(path, settings)`. A missing file, or one that is not UTF-8 or that
`tomllib` or tomlkit can't parse, starts from `TEMPLATE`; an `OSError` on
the read (other than `FileNotFoundError`) is `can't save PATH: REASON`.
Unknown top-level keys, tables included, are deleted. Each §1 key, in §1's
order (`settings_dict`, so `charsets` is a list in canonical order), is
skipped when `doc.item(key).unwrap()` has the saved value's type and value,
and is otherwise assigned with `doc[key] = value`, which replaces it in
place, keeping its trailing comment, or appends it at the end. Then
`path.parent.mkdir(parents=True, exist_ok=True)` and `path.write_bytes`
(follows a symlink, keeps permissions) inside one `try` whose `OSError` is
`can't save PATH: REASON`. Deviations from the brief's suggested shape:
validity is judged by `tomllib` before tomlkit parses (DEC-19, below), and
any `TOMLKitError` (not only `ParseError`) starts from the template.
`doc.item(key)` is used rather than `doc[key]` because tomlkit hands back a
plain `bool` for boolean items through `doc[key]`, which has no `unwrap()`.

**b — the `d` key.** `JumbleApp` binds `d` → `action_save_defaults`, footer
`Save defaults`, after `s`. `check` now records the banner's message in
`self.problem` beside `self.valid`. While invalid, `d` toasts `self.problem`
as an error and writes nothing. Otherwise it resolves `config_path()` at
that moment, calls `save(path, self.settings())`, and toasts
`Saved defaults to {path}`, or the `JumbleError`'s message as an error.
README: the TUI keys table gains `d`; the *Settings file* section gains a
paragraph on `d` (keeps comments, template for a new file, saving over a
broken file repairs it); the TUI intro says `d` saves over a broken file.

### Decisions made

- DEC-19 — a save keeps a file only when `tomllib` (the reader) accepts it;
  tomlkit parses TOML 1.1, so `custom = "\x41"` would otherwise survive a
  save of `custom = "A"` as an equal line and leave a file the command line
  refuses. Spec §5.3 step 1 now says "not valid TOML as §5.1 reads it".

### Doc inconsistencies found

- The brief's notes treated "tomlkit's parse error" as the test for an
  unparsable file. tomlkit 0.15 parses TOML 1.1 (`\xHH` and `\e` escapes,
  times without seconds, multi-line inline tables, trailing commas in inline
  tables), which Python 3.13's `tomllib` rejects, and some of its errors
  (`KeyAlreadyPresent`) are not `ParseError`. Logged DEC-19, updated spec
  §5.3 step 1, and catch `TOMLKitError`. Nothing for the planner beyond
  reviewing DEC-19.
